# CLAUDE.md

Atelier: a local, internal-only app to run and watch agent sessions (Claude, Codex, Gemini): the 세션 보드 is the first screen, the sidebar lists project folders and their sessions, usage, chat history and settings, and the app's chat talks to a session. Documents, canvas, diagrams and plan runs were removed (2026-11-23). Work items are GitHub issues (the older ones in `docs/tickets.md`, which gets no new entries). Agent setup (hooks, sandbox, review tiers): docs/design/agent-setup.md.

## Rules

- Talk to the user in Korean. Code, comments, identifiers, commit messages and this file in English. `README.md` in English, `README.ko.md` in Korean (keep both in sync). UI copy in Korean 해요체, short and plain. New web components follow docs/design/ui-libraries.md (reuse primitives and specialist libraries, one standout per screen, new dependencies proposed only).
- GitHub flow on `chanyee725/Atelier`, integration branch `develop`: one issue per ticket or bug (`gh issue create`, title `E<n>: ...`), branch off `develop` (`feat/`, `fix/`, `docs/`, `chore/`), PR against `develop` with `Closes #<issue>` and what was checked, review findings as PR comments, then `gh pr merge --merge`. No force-push, no deleting remote branches, nothing goes to `main`.
- Commits: English conventional commits, `type(scope): summary`.
- Issue work is summarized only in `Issues/<number>.md` on the issue's branch (Korean, at most 10 lines: title, what changed, PR, checks). No new entries in `docs/` (tickets, design docs) or other documents for issue work unless the issue asks for that document.
- Atelier teams: one team per issue (team rules: plugin/skills/atelier-team/reference/rules.md). After the issue's PR merges, the lead relays the rest of its queue to a fresh team with plugin/skills/atelier-team/scripts/relay.sh, which removes the old team. A lead or the main session may remove a stale lead as defined there.
- The server binds to 127.0.0.1 and its own code makes no outbound requests; fonts and icons are bundled or vendored. It writes only inside the workspace folder (run records under <workspace>/.drawing/), the git project that holds it (<project>/.dispatch/ and session worktrees), and ~/.dispatch/ (shared usage limits). To add a project it may list sub-folder names only (no files, hidden entries or symlinks); it does not write into a linked local folder.
- Agent sessions use the CLIs of providers the user connected: `claude`, `codex`, `agy`. Child processes are limited to those plus `git` and `gh`, all through server/dispatch/cli.js without a shell. The server does not proxy their traffic or read their credentials. From `~/.codex/sessions` it keeps only rate-limit numbers. A Codex API key goes only to `codex login --with-api-key` on stdin.
- A session never runs looser than its chosen permission mode (refuse instead); no bypassPermissions. Codex: plan and auto only. Gemini (agy): acceptEdits, auto, plan through --mode, no --dangerously-skip-permissions. Usage-limit and session-length guards keep their defaults unless an issue says otherwise. Past `handoffMTokens` the system swaps a session for a fresh one with the same settings between turns (setting `autoRotateLong`, on by default): handoff first, teammates, board and plans move to it.
- The lead merges reviewed PRs into develop without a second approval.
- Every non-GET /api request needs the x-drawing: 1 header (x-dispatch: 1 is accepted for the plugin).
- Internal use only: no copied third-party names, logos, icon/illustration/font files or code beyond licensed dependencies with their notices.
- Privacy: no transcripts, auth tokens, API keys, emails or real names stored or logged. Agent transcripts live in memory only. Disk, documents and run records keep metadata only (step states, times, model, token counts, cost, branch, commit, PR number).
  Exception: chats the user opens in the app's chat are saved in <project>/.atelier/chat/ (kept out of git, strongly masked by server/dispatch/chat-redact.js, no images).
- Checks before merging: the tests covering changed files (the Stop hook runs them), typecheck, `npm run build` when `web/` or `shared/` changed, and a headless browser look for `web/` changes. No full `npm test` or e2e unless asked.
- Testing: point the server at a scratch workspace inside a scratch git repo with one commit (in a temp dir), not a real project folder. Tests use the fake CLIs in test/fixtures/fake-cli/; a real claude, codex or agy is refused under npm test. A manual real-CLI run uses the cheapest model at effort low, one session, one-line prompts, and only when a ticket needs it (provider connect, spawn or resume changes).
