# #1031 E716: 팀 역할 — PR 담당·머지 담당, 중복 팀·중복 PR 막기

- 역할 추가: `pr`(PR 담당, Haiku)·`merge`(머지 담당, Sonnet). 둘 다 `gh pr list --state open`으로 같은 이슈·브랜치 PR을 먼저 보고, 있으면 새로 열지 않거나(PR) 멈춰 보고해요(머지).
- 관리자 프롬프트 [병합]·팀 규칙: 관리자와 구현자는 PR을 열거나 머지하지 않고 두 역할에 맡겨요. 머지 담당은 프로젝트에 한 명.
- team.sh: 모든 프리셋에 pr·merge, 세션마다 이슈 번호 기록, 같은 이슈의 살아 있는 관리자가 있으면 그 이름만 출력하고 끝, 살아 있는 머지 담당이 있으면 새로 만들지 않음.
- relay.sh: 같은 검사(넘기는 관리자는 제외), 다시 실행돼도 팀이 두 번 생기지 않아요.
- 웹: 세션 목록의 역할 이름(PR 담당·머지 담당).
- 확인: pr-merge-roles·team·relay·lanes·provider-models·mode-profiles·home-agents 테스트, `npm run build`, 설정 모드별 모델 headless 확인.
